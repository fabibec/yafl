\begin{abstract}
This report details the design and implementation of \texttt{YAFL}, a statically and strongly typed procedural programming language submitted for the Compiler Construction study project.
Designed to explicitly deviate from C-style syntax and semantics, \texttt{YAFL} features a unique pipe-based identifier system, base-$N$ numeric literals, and lazy iterator abstractions.
The language compiles to custom bytecode for an extended architecture of the provided \texttt{VM3} virtual machine, which was modified to support custom opcodes for iterators, slicing, and File I/O functions.
\end{abstract}

\section{General Overview}

\texttt{YAFL} stands for "Yet Another F... Language". The variable "F" reflects the programmer's current sentiment towards the language: \textit{Fabulous} when it compiles, \textit{Fun} when writing algorithms, or \textit{Frustrating} when debugging.

\subsection{Design Philosophy}
The core design objective of \texttt{YAFL} is to merge the readability of modern scripting languages with the structural discipline of traditional system languages.
\begin{itemize}
    \item \textbf{Expressiveness:} While function signatures resemble \texttt{Go}, the language adopts high-level concepts like generalized iterators and range-based loops (inspired by \texttt{Python}) to reduce boilerplate code.
    \item \textbf{Structure \& Safety:} \texttt{YAFL} retains explicit structure using brace delimiters \texttt{\{\}} and semicolons \texttt{;}. Crucially, it enforces a \textbf{static and strong type system} to identify errors at compile time rather than runtime, prioritizing reliability over flexibility.
\end{itemize}

\subsection{Compiler Architecture}
The \texttt{YAFL}  compiler is implemented in \texttt{C} and utilizes a pipelined architecture to transform source code into executable bytecode. The compilation process consists of the following stages:

\begin{enumerate}
    \item \textbf{Lexical Analysis:} Implemented using \texttt{Flex}, this stage scans the input source code and converts character streams into a sequence of tokens.
    \item \textbf{Parsing:} Implemented using \texttt{Bison}, this stage consumes the token stream to construct the Abstract Syntax Tree (AST), representing the hierarchical structure of the program.
    \item \textbf{Optimization:} Additional pre-processing passes traverse the AST to perform Constant Folding and Dead Code Elimination.
    This simplifies the tree structure before it is processed further.
    \item \textbf{Code Generation \& Semantic Analysis:} The AST is traversed to lower the program into the custom bytecode instruction set for the \texttt{VM3} virtual machine.
    During this traversal, semantic analysis is performed on-the-fly.
    This includes symbol resolution, strict type checking, and argument validation, ensuring that only valid and type-safe programs result in executable bytecode.
\end{enumerate}

\subsection{Numeric and String Literals}
Moreover, the language supports a highly flexible number format. Beyond standard decimals, numbers can be prefixed with a base (2-16) using the hash syntax \texttt{base\#number}.
If no base was provided (\texttt{\#number}), the literal will be interpreted as a hexadecimal number.
\begin{itemize}
    \item \textbf{Base-N Floats:} This base logic extends to floating point numbers. Both the integral and fractional parts are interpreted in the specified base (e.g., \texttt{16\#F.8} equals $15.5$ decimal).
    \item \textbf{Formatting:} Underscores are ignored to allow digit grouping (e.g., \texttt{10\#1\_000}).
\end{itemize}

String literals are delimited by double chevrons (\texttt{>>...<<}), avoiding standard quoting issues. The caret (\texttt{\^{}}) serves as the escape character, supporting hex insertion (e.g., \texttt{\^{}xAA}) and standard escapes like \texttt{\^{}n}.

\subsection{Assignments and Operators}
The assignment operator is \texttt{<-}, emphasizing data flow. This allows the equals sign \texttt{=} to be repurposed for comparison, a significant deviation from \texttt{C}.
\begin{itemize}
    \item \textbf{Comparison:} Equality is checked using \texttt{=} (not \texttt{==}). Inequality is denoted by \texttt{\textasciitilde=} (resembling \texttt{MATLAB}), replacing the traditional \texttt{!=}.
    \item \textbf{Polymorphic Operators:} Some arithmetic operators are overloaded for types other than numbers, specifically:
    \begin{itemize}
        \item \textbf{Concatenation (\texttt{+}):} Joins two strings or merges two arrays.
        \item \textbf{Repetition (\texttt{*}):} Repeating a string or array $n$ times (e.g., \texttt{>>ab<< * 3} results in \texttt{>>ababab<<}).
    \end{itemize}
    \item \textbf{Logic \& Bitwise:} The keywords \texttt{and}, \texttt{or} and \texttt{not} are used for logical and bitwise operations, replacing \texttt{\&\&}, \texttt{||} and \texttt{!}.
    \item \textbf{Increment/Decrement:} The operators \texttt{++} and \texttt{-}\texttt{-} are postfix-only. Unlike \texttt{C}, they execute the operation and return the updated value \textbf{immediately}.
\end{itemize}

\section{Language Features}

\subsection{Type System}
YAFL is \textbf{statically and strongly typed}, ensuring strict type safety at compile time with zero-initialization semantics.
Implicit casting is not permitted; conversions must be explicit (e.g., \texttt{to\_float}).
The type system supports:

\begin{itemize}
    \item \textbf{Value Types:} \texttt{int}, \texttt{float}, and \texttt{bool}. These are effectively passed by value.
    \item \textbf{Reference Types:} \texttt{str} and \texttt{arr} (typed arrays). These are passed by reference. Although \texttt{str} is a reference type, it is treated as a first-class primitive in contexts such as \texttt{match} statements and comparisons.
    \item \textbf{Lazy Sequences:} \texttt{range\textquotesingle int}.
    \item \textbf{Special:} \texttt{none} for empty returns.
\end{itemize}
Composite types (e.g., \texttt{arr\textquotesingle arr\textquotesingle str}) are supported.
Uninitialized variables default to zero values (0, 0.0, \texttt{No}, or \texttt{>><<}).

\subsection{Control Structures}
\textbf{Conditionals:} Standard \texttt{if-elif-else} structures are converted to nested \texttt{if} statements.

\textbf{Loops \& Iterators:} The \texttt{while} loop operates on boolean conditions.
The \texttt{for} loop uses iterators (syntax: \texttt{for <type> |v| in <iterator>}).

\begin{itemize}
    \item \textbf{Lazy Evaluation:} The \texttt{range()} function is implemented as a lazy iterator. Instead of creating a full array on the virtual machine stack, the compiler emits the \texttt{MKRANGE} opcode, creating a lightweight state object \texttt{["\_\_RANGE\_\_", current, stop, step]} on the stack.
    \item \textbf{Generic Iteration:} Arrays and strings are wrapped by the \texttt{MKITER} opcode into a uniform container (\texttt{[iterable, current, len]}).
    The \texttt{ITER\_NEXT} opcode handles traversal transparently, by updating the iterator and pushing the next value or an exit signal.
    \item \textbf{Flow Control:} The operators \texttt{next} and \texttt{stop} (equivalent to continue/break) utilize a compile-time "loop stack".
    This stack tracks jump targets, allowing the compiler to back-patch exit addresses once the loop body is fully generated.
\end{itemize}

\textbf{Match Statement:}
The \texttt{match} statement can replace complex \texttt{if-else} chains. Since \texttt{YAFL} allows matching on strings, a simple jump table is insufficient.
\begin{itemize}
    \item \textbf{Implementation:} The compiler generates a hashmap mapping case literals to bytecode addresses.
    \item \textbf{Execution:} The custom \texttt{SWITCH\_LOOKUP} opcode performs a hash lookup at runtime to determine the jump target, ensuring $O(1)$ performance even for string keys.
\end{itemize}

\subsection{Function Architecture}
\texttt{YAFL} supports advanced function features requiring a custom symbol table and multi-pass compilation.
\begin{itemize}
    \item \textbf{Unified Symbol Table:} Built-in functions are pre-registered in the same custom symbol table as user-defined functions.
    This simplifies the parser, as built-ins like \texttt{args()} (returns commandline arguments) are treated exactly like standard calls.
    \item \textbf{Execution Strategy (CALL\_PC):} The standard \texttt{VM3} virtual machine resolves function calls by name.
    This is insufficient for \texttt{YAFL's} overloading support, where multiple functions can share the same name.
    To solve this, the custom \texttt{CALL\_PC} opcode was implemented. It dispatches calls to a specific bytecode address (Program Counter), ensuring the correct overloaded signature is targeted.
    \item \textbf{Overloading:} Functions are identified by a signature combining the function name argument types and their order, allowing multiple definitions (e.g., specific \texttt{to\_int} implementations for different types).
    \item \textbf{Default Arguments:} Trailing arguments can have default values.
    The compiler enforces that all subsequent parameters also possess defaults.
    \item \textbf{Forward References (Two-Pass Generation):}
    To allow calling functions before their definition, the compiler uses a two-pass approach.
    \begin{enumerate}
        \item \textbf{Registration:} In the first pass all function signatures are registered in the symbol table.
        \item \textbf{Body Generation:} During the second pass function bodies are compiled.
        If a call references a not-yet-compiled function, the call site is added to a "fixup list."
        \item \textbf{Patching:} Once the target function is compiled, its start address is backpatched into all pending call sites in the fixup list.
    \end{enumerate}
\end{itemize}

\section{Optimizations}
To ensure efficient bytecode execution, the compiler performs a dedicated optimization pass on the AST prior to code generation.

\begin{itemize}
    \item \textbf{Constant Folding:} Arithmetic expressions involving literals are evaluated at compile time.
    For example, sub-expressions like \texttt{3 * 4 + 2} are reduced to \texttt{14} in the AST, decreasing runtime instruction count.
    \item \textbf{Dead Code Elimination:}
    \begin{itemize}
        \item \textbf{Unreachable Statements:} Code following control flow interruptions (e.g., \texttt{return}, \texttt{next}, \texttt{stop}) is detected and pruned.
        \item \textbf{Branch Pruning:} \texttt{if} and \texttt{match} structures with constant conditions are simplified.
        If a condition is known to be false at compile time, the entire branch is discarded. If true, the conditional wrapper is removed, and only the body is retained.
    \end{itemize}
\end{itemize}

\section{Toolchain and Usage}
The \texttt{YAFL} ecosystem mimics a standard two-stage compilation process, distinguishing between compilation and execution environments.

\begin{itemize}
    \item \textbf{Compiler (\texttt{yaflc}):} Transforms source files (\texttt{.yafl}) into bytecode (\texttt{.yaflb}).
    It supports the \texttt{-v} flag to export the AST as Graphviz \texttt{.dot} and \texttt{.svg} files, allowing for visual verification of the parsing and optimization stages.
    \item \textbf{Bytecode Executor (\texttt{yafl}):} A modified version of \texttt{VM3} that executes the bytecode.
    It accepts commandline arguments, which are accessible to the user program via the \texttt{args()} builtin function.
\end{itemize}

\section{Demonstration Programs}

The capabilities of \texttt{YAFL} are demonstrated through four included programs:
\begin{enumerate}
    \item \textbf{Game of Life}: Implements Conway's Game of Life to showcase the language's handling of multi-dimensional arrays and nested loops. It is able to read patterns from standard \texttt{.rle} files to create an animated visualization in the terminal.
    \item \textbf{Run Length Decoder}: A recursive descent parser for decoding run-length encoded strings (e.g., \texttt{43[ab]}). This program demonstrates recursion, string manipulation, and conditional logic.
    \item \textbf{Black Jack}: A fully interactive card game simulation. It highlights the use of the \texttt{rng} builtin for game logic, \texttt{input\_str} for user interaction, and extensive control flow using \texttt{match} and \texttt{if-else} structures.
    \item \textbf{Language Demo}: A comprehensive showcase of specific language features including function overloading, slicing, and pattern matching.
\end{enumerate}

Other modifications of the source code include:

\begin{itemize}
    \item Renamed \texttt{stack\_t} to \texttt{vmstack\_t} due to name collision with stack.h required by signal.h.
    \item Rewrote type casting to include parsing of \texttt{YAFL}s custom number format from string.
    Added additional functionality for some types.
    \item Changed \texttt{exec\_t} and \texttt{exec\_new} to accept commandline arguments.
    \item \texttt{val\_mul} now supports multiplication of arrays and numbers.
    \item \texttt{arr\_copy} now creates deep copy even for nested types.
    \item \texttt{str\_add\_buf} uses exponential growth in order to trigger less reallocation when concatenating multiple strings.
\end{itemize}
